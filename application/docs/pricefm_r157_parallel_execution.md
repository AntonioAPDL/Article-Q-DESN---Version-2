# PriceFM R157 execution and continuation

R157 adds a source-bound Slurm lifecycle and the cached Normal screening worker
and scientific controller. It preserves the original FI/DK2 candidate universe,
training splits, seeds, four clocks, eight-origin chunks, H96, 100 paths,
nomination and stability rules. Cached screening creates no new model fits.
An accepted cost panel never admits screening automatically.

The implementation is a feature lane. Passing metadata tests does not establish
numerical compatibility, a successful cluster allocation or scientific repair.
The actual phase receipts, finite resource grants and canonical ledgers control
those decisions. Historical qualification attempts and charges remain spent.

## Controller resources and proof boundaries

The initial proposed240CPU controller allowance was insufficient to bound all
SSH, transfer and readiness operations. R157 supports a new prospective720CPU
scope: three230CPU claim reservations plus publication30. Each initial claim
prices metadata20×3, transfers6×11, one READY watch11, fresh admission20 and
parent60 =217CPU, with13CPU reserve. This is separate from original numerical,
cost-panel and assessment scopes. Creating it requires an exact root admission;
this document does not create a scope or refund history.

Every lifecycle remote operation is charged before I/O. Each administrative
parent reserves an8CPU lifetime slice against its original60CPU pool. Interrupted
slices are never refunded. Missing CPU receipts or measured overruns block further
I/O. Process limits and conservative reservations are used; there is no claim of
aggregate cgroup enforcement. Measurements explicitly identify final-receipt
overhead covered by upper reservations. Ordinary status polling is at least300
seconds apart. BeeGFS cross-node inotify is not assumed: a single bounded SSH
stream checks one exact READY path, with10CPU and the original queue deadline.

The compute worker receives original bytes of explicitly named validator-read
JSON proofs. It checks every staged proof hash. It does not recursively transfer
the historical provenance graph, which includes retired paths, native libraries
and arrays. Historical opaque references retain their original hashes. Every
scientific input remains independently allowlisted and hash-checked before use.

An optional shared input cache requires a separate exact source/plan/site-bound
`--control` packet and prepriced PREFIX control reservation. Its transfer and
bounded remote streaming verification are metered. A validated cache receipt
permits `--link-dest`; workers still verify every original input byte.

## Main commands

Use the pinned Python with `-B`, administrativeCPU31 and this lane's
`application/scripts/pricefm` on `PYTHONPATH`. `--help` lists exact arguments.

* `pricefm_hb.admission`: fresh read-only request; no authority or submission.
* `pricefm_hb.lifecycle prepare`, `submit-held`, `issue-authority`,
  `release-and-activate`, `status`, `collect`, `cancel-held`.
* `pricefm_hb.prefix_control create-plan`, `draft-master`, `adopt-master`,
  `admit-study`, `open-wave`, `calendar-observation`, `prepare-release`,
  `prepare-assessment`, `queue`, `advance`, `stage-cache`.

`cancel-held` requires the exact known server job to be PENDING. Ambiguous
submission/transfer states retain spent claims and require reconciliation.
Running baseline science is never cancelled by this path. The original seven
repair targets and29 dependent tasks require their own validity barriers and
source-aware global closeout; two local pilots cannot close all seven targets.
