## Public API and dispositions

`502_screen_pricefm_stage_r151_region.py` is standard-library-only at import.
`metadata-audit` checks parent inputs without preparing a runtime or writing
DATA. `prepare` requires the clean committed dedicated R151 branch and writes
the immutable preparation and252 potential task descriptors. Those descriptors
are not 252 admitted executions; only 63 D and at most 27 S can enter the DAG.

The module exposes `prepare`, `read_preparation`, `task_complete`,
`task_by_name`, `queue_state`, `advance`, `estimate_task`,
`completed_CPU_charge`, `worker` and `finalize`. `advance` needs an explicit
`remaining_CPU_seconds` and optional pinned `budget_view` only at the extra
seed decision. The outer resource controller must drain workers before
advancing phases so the last final-seal-bound CPU receipt is available.

Queue phases are `BENCHMARK`, `DEFERRED_UNFUNDED_PREFIX`,
`DETERMINISTIC_POOL`, `NOMINATION_REQUIRED`, `NOMINEE_SEED0`,
`EXTRA_SEED_DECISION_REQUIRED`, `MATCHED_MC_UNFUNDED_PENDING`,
`MATCHED_FULL_MC` and `READY_FOR_ASSESSMENT`. An unfunded complete prefix
is a terminal budget disposition with `scientific_complete=false`.
Unfunded matched extra seeds remain explicitly pending and cannot produce
a complete scientific assessment. The outer finite workflow may drain and
record that resource deferral without opening another region or AL stage.

Every worker requires a source-matched R151 policy receipt, actual unit
InvocationID/cgroup, one physical CPU15–29, actual SCHED_IDLE, idle I/O and
all six vendor thread variables set to 1. `worker --name __benchmark__` handles the
single benchmark. `worker --name __finalize__` or `finalize --cpu CPU
--policy-receipt PATH` performs the strict retained-array/loss replay inside
an owned idle validation payload. Finalization is accounted from the wave's
validation reserve rather than new forecast compute.

Before numerical imports, each worker independently resolves exactly one
immutable regional lease ID and verifies its source, preparation, boot,
expiry/duration, nonrenewing flag and outer lifetime/context backlinks. A
benchmark cannot consume a numerical wave, and a benchmark admission cannot
release D/S work. Its only nonbenchmark payload is a strictly deferred-prefix
assessment after the benchmark has sealed. Actual policy proof PID, process
start ticks and boot ID must match the current process; the intentional
bootstrap-to-producer exec is allowed to change argv.

A stable practical lead yields at most one **proposal**, not an AL launch:
same-package Normal driver and AL receiver, 500 paths, 18 forecast components,
