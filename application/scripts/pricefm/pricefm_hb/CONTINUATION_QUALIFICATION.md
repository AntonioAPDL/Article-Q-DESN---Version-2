# PriceFM continuation qualification

This added feature lane leaves the existing scientific/controller/runtime files and running campaigns unchanged. It implements saved-training metadata diagnosis, a native Hummingbird preflight, an owned-helper startup adapter, finite two-role compute qualification, and an opaque runtime archive builder.

Metadata tests establish source behavior only. Live qualification failures remain in the PriceFM tracker and confer no runtime, ABI, numerical parity, target bridge, or screening acceptance. No added tool authorizes a scientific fit, winner replacement, official-test selection, broad grid, automatic retry, or expired-scope replay.

## Saved-training evidence

The training_metadata_collect module and pinned bootstrap collect bounded JSON metadata from explicit Jerez roots; the compressed raw packet remains authoritative. Derived training-context records are explicitly typed with original path/hash/stat provenance. Scientific arrays and official-test response records are excluded. training_metadata_audit_bind binds saved records to a uniform training_metadata_audit config. The audit preserves eligibility, three equally weighted internal splits, original frozen winners and eight distinct NO4 convergence certificates. A frozen-winner mismatch fails closed and requires diagnosis; it never selects a replacement.

## Runtime and cluster gates

batch_preflight performs fixed native Slurm/module queries without submission. startup_helper uses unchanged profile_supervisor and source-bound purpose-specific grants for owned helper processes and exact R metadata startup. Synthetic helper tests are distinct from actual kernel and R startup proofs.

startup_batch sends native SSH/SFTP/Slurm administration only to login. Its worker and kernel execute only in the declared compute allocation. The two one-shot roles are runtime inventory with six owned-helper cases, then exact R4.6 startup metadata after accepted inventory. Each action requires its real outer guard receipt; pending internal markers do not establish acceptance. One canonical registry/namespace, durable spent roles, complete primary/step accounting, independent READY/return review and original expiry/resource limits remain mandatory.

runtime_carrier retains the earlier bank implementation and its failed attempts. runtime_archive supplies a separately scoped direct streaming alternative. Its same-shape opaque synthetic algorithm qualification and actual independent review must pass before a real runtime archive. The authoritative tar.gz contains regular runtime files only, with its byte-verified manifest beside it. Archive success does not prove R startup or host ABI.

## Reproducible operations

Use immutable tracker configs, source freezes, prospective scopes, actual root grants, independent reviews, actual guard receipts and native accounting. Never copy a sample status into a PASS receipt. Configure a fresh source-published canonical registry and namespace; never reuse a spent role or expired authority. Source-specific schemas are enforced by the modules and tracker runbook. No local R/NumPy/model execution belongs on administrative CPU31.
