# New NO3 pilot I/O: source implementation and qualification boundary

This directory implements the new pilot I/O contract, native bounded writer, R provenance/import/checkpoint glue, and complete one-attempt R bootstrap. The original five scientific files, R525, W191, its native boundary, original H, old scopes, mathematical limits, seed, priors, scalers and test-selection policy are unchanged. No grant, job or accepted scientific result is produced here.

The author fixture invocation passed 29 metadata/source tests once. No R was run or parsed; no native code was compiled or loaded; no target payload or numerical array was opened on administrative CPU31. C/R compilation, ABI/syscall probes, actual R serialization/retention, real current ownership and the whole-purpose price remain required compute qualification. Source acceptance is not numerical admission.

## Interfaces and ordering

- pilot_io_contract.validate_request validates the exact closed I/O descriptor and always returns can_write=false/runtime_admitted=false. Arbitrary claimed bridge/measurement descriptors never become proof.
- pilot_io_contract.validate_return requires every completed remote checkpoint and evidence, complete core/owner proofs, deterministic count-only unique{1,ceil(N/2),N} useful return, original 16 MiB/file and 64 MiB total caps. It does not verify actual bytes or admit a result.
- pilot_bootstrap.R takes six arguments: owner-spec path/hash, authority path/hash and source-review path/hash. Owner spec pins io_request and canonical acknowledgement_path; its source map includes pilot_io/pilot_owned_io.R. The bootstrap emits the exact shared source-parse frame, delegates one real native ACK, then calls the one-attempt pilot. It returns only a candidate.
- r200_begin_after_real_ack pins source/metadata, preloads the exact I/O DLL inertly, parses R sources and prepares the frozen runtime definitions/namespace before the native barrier. It then invokes the actual pinned r157 scientific boundary. After that call, it reconciles the parent gate against current child/parent PID/birth/boot/job/node/UID/source pins. A JSON ACK flag, environment flag or authentication callback cannot construct a native capability.
- r200_verify_all_input_bytes makes immutable sealed memfd copies of three scientific inputs plus ten exact proof aliases after ACK. All hashes are checked before numeric design or RDS interpretation.
- r200_import_verified_factors compares the entire stored scientific source/provenance, logical X/y references, original failed bindings, target, prior controls and initialization semantics before the unchanged R525 factor validator and explicit objective. It never reconditions factors.
- r200_make_bounded_engine replaces only the newly constructed engine environment's checkpoint binding and verifies its mathematical body hash is unchanged. Every completed sweep keeps full factors, schedules, RNG and evidence before the unchanged stock stop decision.

## Physical reservation and failure behavior

All300 possible checkpoint pairs and eight R outputs are reserved: final_state.rds, independent_certificate_full_state.rds, terminal_core.json, beta_mean.bin, beta_cov.bin, vb_trace.csv, checkpoint_index.json and proof/COMPUTE_IMPORT_PROVENANCE.json. Separately owned parent/guard proofs still require their own bounded owner contract and are part of useful return.

The C helper binds an opaque capability to current UID/PID/parent birth, actual Slurm job/node/cgroup, Seccomp/NoNewPrivs, finite expiry and inherited actual FLOCK. It checks complete retained slots plus mandatory headroom, physically allocates every slot with posix_fallocate, verifies actual allocated blocks and checks postallocation headroom. There is no sparse/ftruncate-allocation fallback.

Each exclusive .part inode is opened without following symlinks. The custom connection rejects a cap-crossing write before issuing it, writes at most64KiB per kernel chunk, and supports binary and formatted CSV output. Successful close/fsync and complete serialization precede commit. Only unused padding of the completed slot is truncated; every future slot remains physically reserved. Linux renameat2(RENAME_NOREPLACE) atomically refuses a raced/preexisting final. Unsupported APIs/ABI stop without an overwrite fallback.

Overflow, serialization error, EOF, input change, unsupported syscall, expiry, owner change, failed persistence, raced final or partial output spends the capability. Paid partials/reserves are retained, never silently removed or retried. Native read-only slot inventory can describe a failed capability; live input/write operations require a separate current-lifetime check. Committed pairs1..N and all unused future reserves must be accounted in the full remote seal; reserves are not completed checkpoints.

## Mandatory future compute qualification

1. Pin compiler/R version, R_CONNECTIONS_VERSION1 header, build/DLL/source hashes and inert initialization. The custom-connection header explicitly is not a stable R API.
2. Prove current native parent parse/ACK and the new syscall/ABI behavior. No helper fork is allowed after scientific TSYNC; this implementation creates none.
3. Qualify real physical allocation/quota/headroom, binary/text round trips, exact/overflowing writes, raced-final refusal, close/persistence failures and paid-partial/reserve accounting.
4. Prove actual memfd seals, source inode-change rejection and hash-before-interpretation behavior.
5. Accept actual RDS provenance, unchanged factor/objective parity and whole-context finite price, then issue new input/runtime/owner/return authorities.

Running pilot_bootstrap.R as a supposedly free measurement would invoke the one optimizer attempt and is forbidden. Build/ABI/I/O probes need a separately sourced/priced nonoptimizer harness and current owned compute qualification. Existing W191 diagnostic qualification is not inherited by this new DLL or pilot.
