# Qualification-only native-pilot to typed-v2 consumer

This is the next source-only step after the native numerical prototype. It
converts **one already successful, independently closed original draw/origin
pilot** to the existing lossless typed-v2 numerical representation. It does
not make that representation a production worker, canonical ledger result,
scientific score or article asset. Existing generated-only APIs, v1 DKW
workers/receipts, controllers, source manifests and scorers are unchanged.

## Inputs and numerical meaning

`scripts/mq_qualified_pilot_typed.R` checks the following before constructing
an `integrated_quantile_forecast_shard_v2` and one-member typed block:

- the actual new-source native replay purpose, source commit/tree, original
  model/chain/parameter row, observed origin, scientific namespace and target;
- successful numerical status, source-bound training freeze, terminal output
  membership/hashes, successful stop-post and independent final supervisor
  readback, plus the separate finalizer's native time/cost closure;
- exactly 210 frozen candidates, the original split diagnostic and final
  streaming state, on seven levels and 30 horizons;
- original training IDs 1–65,536, disjoint validation IDs, declared looks and
  alpha spending, unchanged error tolerances, and the complete128-ID block
  receipt chain;
- a fresh recomputation of every existing `iqr2` endpoint bound. A producer's
  PASS boolean cannot waive this numerical check.

No pilot source commit is hardcoded. A failed or REVIEW pilot cannot be
converted by substituting its scope string or marking it successful. Previous
failed purposes, arrays, logs and terminal receipts are neither deleted nor
rewritten. Reusing original namespaces is explicitly not a new independent
statistical replication.

The parameter draw is never pooled, thinned or reweighted. Numerical identity
fields explicitly record their **qualification-only** meaning: the prepared
prefix manifest is the input manifest, and the original one-unit contract is
the task manifest. These are not silently relabelled as complete campaign
inventories. Converter source/purpose identity is recorded separately from
the numerical producer's source. All source, original-unit, stream, candidate
freeze, terminal and selected evidence file pins survive in `PROVENANCE.json`.

## Separate executable read grant

`scripts/consume_mq_qualified_pilot.R` requires a new, external SHA-pinned
`mq_qualified_pilot_consumer_purpose_v1`. Its exact schema distinguishes
`mode=convert` from `mode=readback`; the former permits only selected own-pilot
evidence, and the latter only the new compact packet. Model, future-truth,
refit, scoring, ledger, production and article permissions must all be false.

The fixed native ceiling is CPU30, CPU120 seconds, TERM119/KILL1,2GiB address
space and16MiB output. The exact clean committed source closure, native
R4.6/digest0.6.39, vanilla one-thread environment, affinity, OS limits and shared
timeout process group are checked. Every actual grant still requires the
coordinator's fresh ownership/resource and supervisor review. Loading this
module or passing a generated test issues no grant.

Before RDS deserialization, the reader resolves the exact role basenames and
hashes, source/purpose/terminal links, manifest membership, and the training
freeze. The only pilot RDS readers are `frozen_training_candidates.rds`,
`training_split_diagnostic.rds` and the named final declared-look stream. No
fit, posterior, original design, simulation fixture, truth or historical
training-array reader is provided. All selected inputs are rehashed after
conversion. Metadata and selected evidence total at most32MiB; each input is
at most8MiB. The outputs are a fresh ignored `typed_block.rds`,
`PROVENANCE.json` and `artifact_manifest.csv`, never an article directory.

For independent readback, issue a separately pinned `mode=readback` purpose
with the exact produced provenance SHA. The provenance also anchors the exact
typed-block file SHA, preventing a resealed replacement block and manifest
from being substituted underneath unchanged provenance. A fresh R process checks packet
membership, source/provenance associations, typed integrity and every bound
using the unchanged `iqr2` decoder before returning a nonproduction proof.
The code does not call the generated-only `mqw2` functions with authentic
inputs or change their scope strings.

The32MiB limit is a **distinct selected-input inventory**, not a claim of
32MiB total I/O. Conversion hashes each selected input before and after
(at most64MiB), decodes the three selected RDS files once (at most24MiB), and
parses the remaining selected metadata once (their exact serialized size).
These code-path counts are retained in provenance. Software-source hashing,
Git metadata checks, output serialization/hashing and independent compact
readback are additional work within the native CPU/wall/memory ceilings;
they are not misreported as measured OS I/O. Readback validates only the new
bounded packet, not the original pilot files again. Role basenames, file sizes
and nonsymlink checks precede each compact metadata/RDS read. The converter
creates its fresh owned output before input consumption and retains a failure
receipt if a guarded conversion fails.

Command form (not authorization):

```text
Rscript --vanilla scripts/consume_mq_qualified_pilot.R --contract PRIVATE_JSON --sha256 SHA --execute
```

## What this does not finish

This closes only a genuine qualification-consumer interface. Canonical v2
claim/worker/central acceptance, source-qualified recovery/adoption, real
scoring producer bindings, complete native inventories/weights, campaign
confidence and score-error policy, full retention/cost pricing, method/host
admission and a campaign grant remain separate. No canonical ledger mutation
or oracle access is performed. A one-unit conditional CDF bound is not a
simultaneous whole-campaign guarantee or particle-filter certificate.

Generated tests create all of their own metadata and evidence. They retain
the authentic schema geometry but contain synthetic constant-CDF values,
exercise adversarial source/status/freeze/stream/terminal mutations, serialize
and independently decode the compact result in another R process, and never
read an actual pilot or model file. Their successful result is not evidence
that the genuine pilot or full campaign has completed.
