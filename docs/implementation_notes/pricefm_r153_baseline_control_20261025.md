# Explicit additional baseline control

The October 25 implementation request authorizes the reviewed baseline-only
recovery. R153 does not replenish R152's exhausted three-generation allowance.
It records exactly one explicitly additional activation, a cumulative owner
count of four, and a separate finite grant: seven days and 28,800 conservative
control CPU seconds. Owner and guardian declare `Restart=no` and
`KillMode=process`; the guardian never restarts or signals a numerical worker.

The immutable R152 state, ownership epochs, failed receipts, original master,
expired cached clock and closed cached ledger remain unchanged. The only
create-once extension to that namespace is `baseline/explicit_successor.json`.
It points to the separately source-bound R153 authority and runtime. A reader
must resolve and validate this explicit successor; the old third-generation
owner is not relabelled healthy.

## Exact process identity policy

Script 513 composes immutable R152 read/packet/region/launch helpers and the
R141 mathematical producer through explicit functions. It does not patch
module globals or rewrite observed process metadata.

Every new or recorded session child is classified. Owner/guardian and Python
controller identities stay exact. Scientific workers require the frozen
Python entry/region/task/CPU argv, UID, lifetime, ancestry, session, service
cgroup and declared lane. The frozen producer imports/validates its source
before its worker pins itself; an inherited lane mask is accepted only during
that source-defined bootstrap, for at most 120 seconds, with no R child yet.
A previously singleton-pinned worker cannot regress to a broad bootstrap mask.
All numerical R execution requires the worker's exact single CPU.

The one added cwd state is the Normal R fitter's exact canonical package path,
alongside its recorded launch directory. It is bound to the task, preparation,
immutable producer script and source pins. Rscript/native-R argv forms are
exact; extra files/eval flags or duplicate contract flags fail closed. AL uses
its original launch cwd and pinned CRAN library/manifest/helper contract.

First observation does not trust an arbitrary same-named contract. The full
Normal dictionary is reconstructed from the frozen template/protocol/task and
sealed sufficient-statistics terminal. The full AL dictionary includes exact
certificate limits, sample counts, solver budget, design/parent paths and seal
hashes, posterior target and the original deterministic seed. The seed rule is
implemented with stdlib SHA256/JSON only, faithfully matching the frozen
recursive-normal → R120 → R123 producer chain. Tau0 target strings use `.17g`.
Normal 2000 and AL 300 caps remain distinct and literal. Registered immutable
contract/preparation hashes are rechecked; no posterior object is imported.

Unknown live children fail closed. The only auxiliary roles are the precise
read-only git commands and lscpu invocation emitted by the frozen producer,
with validated ancestry and cwd. Protected-process reading and empty-exit
handling retain the prior bounded, positive-terminal/gone rules. Additional
UID/parent reads likewise require positive exit evidence or a bounded stable
reread, rather than treating missing metadata as process absence.

## Single activation and publication

Script 514 owns release, private proof, staging, claim and launch. Both declared
control units wait at most 30 seconds for one immutable attestation binding
their actual PID/start/boot/argv/cwd, InvocationID, service policy, source and
authority. The owner takes the original legacy dispatch fences and its own
exclusive runtime lock, validates surviving sessions and publishes readiness.

No new region is dispatched before 514 observes healthy owner/guardian records
and creates the explicit successor registry. The initial state-to-first-epoch
publication gap is a bounded guardian wait only with fresh positive owner/unit
and matching authority/activation evidence. A later missing epoch, stale lease,
unknown process, source drift or resource failure stops dependent dispatch.
The spent activation is not retried.

The two original controller sessions are adopted without model signals,
restarts or affinity movement. The scientific region sequence is unchanged.
Lane B returns to CPUs 15–29 only at a naturally drained region/controller
boundary after independent cached-drain proof. Its loan-return receipt is
written only in the new R153 runtime, never into old R152 state.

RHS screening exclusions must not be mistaken for AL control failures. The
versioned typed collector preserves finite original-cap RHS exclusions and
quarantines finite required AL300 or Normal-full2000 blockers. It verifies
their full producer contracts, source/task/seal identities and literal
certificate flags. Unknown, nonfinite or mismatched evidence remains blocked.
It never recomputes or relaxes a certificate and never retries a fit.

## Cost and observation cadence

Fresh owner/guardian/process checks run every 20 seconds; the lease is 180
seconds, and bulk source verification runs every 60 seconds. This cadence is a
documented refinement from a five-second proposal: sub-minute control latency
is insignificant beside hours-long fits, while measured redundant observation
cost would consume the finite control allowance too early.

One fresh census may be shared by the two lane decisions within the same poll.
Known PID/root observations are still directly refreshed. Fresh positive exit
proof supersedes an earlier same-cycle census. No PID or liveness proof is
cached across polls. Immutable preparation parsing is reused only after a
fresh SHA each observation; duplicate consumers within that one observation
do not hash the same large preparation again.

Accounting uses owner CPU, guardian CPU, explicit administrative reservations,
prior private-probe debits and a final control tail reserve. It never uses
service-cgroup CPU or `RUSAGE_CHILDREN`, which would incorrectly charge the
scientific model tree. Both the seven-day wall grant and conservative control
CPU ceiling stop further dispatch without signalling models. Completion is a
verified finite nine-region disposition, not global scientific promotion.

integration are outside this controller.
