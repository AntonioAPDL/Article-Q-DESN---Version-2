# Additive scientific runtime and HB qualification route

This lane prepares code and explicit new qualification consumers. It does not
admit a numerical toy, bridge or production pilot and issues no job authority.
Original H, the old2048-file startup gate, the r157 ptrace guard, frozen525
scientific source, installed runtime and old result/failure records remain
unchanged.

## Code carrier

`scientific_runtime_carrier.py` discovers the installed exdqlm1.1.1 CRAN,
digest and jsonlite Imports/Depends namespace closure, verifies the original83
runtime bindings, and reads native DT_NEEDED/version metadata without starting
an ELF or R. It excludes additional package datasets, documentation, tests and
headers; package **code is included**. Precompiled package code and other needed
runtime resources remain opaque. Suggests/LinkingTo are recorded separately;
this is an ordinary namespace-startup closure, not permission to compile new
models or use optional data/functions.

The previously verified680-file baseR carrier is reused without rebuilding it.
New code cannot overwrite a base member. Non-glibc native dependencies are
resolved, pinned and carried; host glibc is not bundled. Actual HB ABI and all
48 namespace versions/paths still need compute proof. The new addon consists
of1599 code/ELF files and163,614,891 bytes in two regular-only archives, each
within the unchanged streaming helper's2048-file/128MiB container limits.

Combined base+addon is2279 files/275,498,747 bytes, beyond the old startup role's
2048-file envelope. `scientific_namespace_plan.py` therefore defines a distinct
new purpose with4096 regular files,384MiB total and64MiB per-file bounds. This
does not edit or waive the old role. Actual acceptance requires independent
review of this new exact source/spec/purpose and separately funded authority.

`scientific_code_install.py` is a concrete compute-only consumer of that new
purpose. It requires exact spec/root/review pins and actual one-CPU Slurm job
identity before extracting code. It validates the exact base, all addon hashes,
disjoint safe regular member names, complete totals and every extracted byte.
It writes only into a new private namespace, never onto the qualified baseR
job's directory, never overwrites a member and retains a failed partial without
retry. The result is code installation, not startup, ABI or numerical proof.

## Actual qualification consumers

`scientific_namespace_fixture.R` loads the48 requested namespaces from their
new library, verifies versions/paths, exdqlm's exact stock CAVI body SHA and
actual loaded DLL hashes. It consumes only metadata/code; optimizer/model/data
counts are zero. This is a new scientific namespace metadata role and cannot
be substituted for the existing base/default R fixture.

`scientific_metadata_owner.py` accepts exactly two zero-target/zero-optimizer
roles: namespace metadata and native TSYNC boundary metadata. It requires a
new exact spec/root/independent-review contract, live one-CPU/8GiB/nonrequeueing
Slurm scheduler and cgroup evidence, complete source/runtime/fixture pins,
single-thread environment, new private job flock and a full finite600CPU/1200
wall proposal with separate outer accounting. It uses the original r157
ptrace implementation unchanged. Only exact newly owned lifetimes can be
signalled. A failed/unreaped owner cannot yield approval; its output remains
consumed/quarantined and unproved drain requires fresh reconciliation.

The H child filter denies ptrace syscall101, while the scientific guard uses
ptrace and a kernel-attested TSYNC/ACK barrier. Therefore this native owner runs
directly inside its separately admitted Slurm allocation, **never below H**.
No existing supervisor policy is relaxed. H can still guard ordinary code
installation/native control roles where appropriate. A successful H metadata
receipt is not a substitute for the native scientific boundary proof.

`scientific_boundary_fixture.R` first proves namespace/body metadata, then
loads the original boundary library and invokes its unchanged TSYNC primitive.
The owning tracer must verify the actual filter program/kernel return before
ACK. Child output alone is not proof. The owner's classifier requires full
kernel ownership, reaping/drain/CPU proof and actual TSYNC+ACK for the boundary
role; a namespace-only pass cannot become a boundary pass. Root still reviews
complete return/outer-parent and primary Slurm accounting before acceptance.

## Numerical source port and remaining stages

Frozen toy and bridge entrypoints hard-code Muscat CPU30 and its old permit.
`hb_scientific_adapters.py` generates separately named HB authority/path ports,
not edits to those files. The toy suffix beginning with its original scientific
source loads, and the bridge/pilot suffix beginning with `read64`, remain
byte-identical. The added prefix requires the new Slurm job/affinity/root
contract, private flock, source review and previously accepted boundary proof.
It preserves the toy's8 optimizer calls/30 iterations/n128/p32 and the real
bridge0/pilotAL300 contract. Bridge library relocation is an explicit path
alias, with fixed scientific sources and target hashes retained.

`scientific_stage_bootstrap.R` loads the verified namespace and original C
boundary under the owning tracer, waits for its real proof/ACK, and only then
sources the separately approved numerical entrypoint. Its environment flag
follows that handshake and does not replace it. These generated R sources
have not yet been parsed or executed on compute. Python tests prove suffix
byte identity and metadata gates, not R correctness or numerical parity.

The cost model accounts separately for transfer, extraction, source/runtime
hashes, namespace startup, owner/control, payload, failed stop/drain, checkpoint,
return/finalization, outer parent and canonical primary Slurm CPU. Components
are attribution, not amounts to add again to an inclusive primary job. Every
new stage needs a complete prospective envelope and feasible absolute calendar;
the proposed600CPU/1200wall qualification ceilings are not reservations or
runtime guarantees. Whole-campaign ETA follows an accepted pilot and priced
dependency graph, not old task-count throughput or assumed linear CPU scaling.
