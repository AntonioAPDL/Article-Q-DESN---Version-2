## Exact operation and limits

`scripts/native/mq_key_hash.c` calls the public `R_Serialize` API with
version-2 XDR format for each unchanged seven-field named key. It is not a
handwritten approximation to R serialization. The existing installed
`digest` SHA256 path skips the first 14 serialized header bytes. The C
candidate hashes the identical remaining bytes with the existing system
OpenSSL SHA256 API, extracts the same six seven-hex-digit positive words and
performs only the already specified first CMRG step. Signed remainder is
corrected separately for the two native moduli. No R RNG state API,
persistent random state, alternate key or replacement generator is used.

`scripts/mq_native_key_hash.R` loads only an explicitly supplied existing DLL
with its expected SHA256. It requires the declared R4.6.0/digest0.6.39
serialization semantics and the original first-step reference declaration.
The helper is restricted to plain scalar string identities and valid
distinct positive integer path IDs. Strings retain their R encodings;
character labels are materialized before the C call. Unsupported classes,
types, dimensions or runtime semantics fail explicitly. The bounded audit
route retains full raw serialization, digest hex, words and uniforms for at
most 1,024 tuples / 64 MiB of estimated raw audit storage.

The explicit array adapter clones only a function environment to substitute
this candidate's uniforms for the selected call. Existing functions,
canonical defaults, old source guards and production registries are not
modified. Candidate outputs retain false source-authentication, numerical
qualification and production flags. No automatic compiler, data discovery,
model loading or scientific execution is supplied by either helper.

## Generated validation and reproducibility

The standalone test requires an explicitly caller-built `mq_key_hash.so`, its
SHA256 and an existing output directory. It compares complete raw serialized
bytes to `base::serialize`, SHA256 to `digest::digest`, every word to the
original key helper, and exact uniform binary64 values to both the old fast
reference and actual native scoped CMRG calls. Cases include repeated
strings, UTF-8, Latin-1, byte-marked identities, long strings, special
characters, nonconsecutive IDs, integer boundaries, partitions, horizons,
errors, absence of caller RNG state and a forced-GC probe. Three generated
reservoir configurations compare every recursive array/trace/coherence
object through horizon 30; no authentic fixture is opened. Source metadata
and compile/test/native-time receipts belong in ignored local trackers.

Compilation/testing uses the existing compiler and system libraries only,
with `-fno-fast-math -ffp-contract=off`. A new bounded build/test allocation
must price compilation, generated checks and timing together. No compiled
binary belongs in Git. The original implementation is MIT licensed in
`scripts/licenses/mq_key_hash_MIT.txt`; R and the linked OpenSSL 1.1.1k system
library retain their own licenses. No R/digest/OpenSSL implementation code
is copied. This is not a blanket redistribution-license or ABI clearance.

Generated timing may motivate an authentic candidate but cannot establish a
campaign speedup or cost estimate. Actual qualification requires a later
frozen combined source, source/header/compiler/libcrypto/native-R hashes,
runtime enrollment, external finite purpose and resource grant, authentic
array-path parity, precision/stress checks and whole-cost evidence. The old
accepted `47yweuyf` replay cannot be relabelled as this new candidate's
qualification. Production dispatch remains prohibited until its separate
