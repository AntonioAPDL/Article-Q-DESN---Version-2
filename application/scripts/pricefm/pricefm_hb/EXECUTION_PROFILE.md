# Immutable actual-component profiling

`execution_profile.py` executes a prospective, separately funded reference /
instrumented pair. It does not submit a job, change the accepted scientific
source, revise prices, select candidates, fit models or admit screening.
Importing the module and running its private tests use the standard library.
Numerical imports are inside an admitted compute child only.

## What actually executes

Both fresh child interpreters run the complete original
`prefix.component_loop`: every original origin at all four clocks, every chunk
in original order, the unchanged predict/retained-array arithmetic and RNG,
all chunk/full validators, full concatenation/metrics/serialization, original
seals and cleanup. The accepted source, AST and referenced-global surface are
verified. Reference runs first without phase wrappers. The instrumented run
passes explicit adapter/callback wrappers through the existing injection
interface. To time internal seals it compiles the exact unchanged component
AST in a private namespace with one timed `seal_directory` dependency. It
neither changes a frozen module/global nor rewrites arithmetic. The private
global binding surface is recorded as a source constant and tested.

The all-parent PSD preflight belongs to the old COST panel. It is explicitly
marked unexecuted here and is not added to either actual component. A small
component is a bounded qualification, not evidence covering all492 task
identities. Joint geometry/mode/clock/seed gaps retain the old price fallback.

## Authority and lifecycle

The exact JSON request schema is
`r164_actual_component_profile_request_v1`. Its fields are `schema`, `purpose`
(`ACTUAL_COMPONENT_PROFILE`), `profile_plan`, `cost_plan`, `policy`, `study`,
`task`, `task_sha256`, `stage_root`, `execution_order`
(`['reference','instrumented']`) and `storage_mode`
(`DIRECT_RETAINED_SOURCE`). Pins contain exact absolute physical paths and
SHA256s. Metadata can be copied to an admitted remote location; immutable
scientific metadata hashes and original logical input paths remain unchanged.
Scratch copying is not implemented or implicitly funded.

Before any numerical import, `profile_admission.validate_worker` must accept
the new finite prospective policy, reviewed exact sources, exact request and
job-bound authority/attestation, whole paired limits, reserved new funding,
runtime/native libraries and original constraints. A qualification pair and a
later measurement pair have different scopes and preconditions. R163 metadata
preparation and old TEST/COST/opaque permissions cannot grant this authority.
The controller and both children must write exactly the authority's output
root / role in a separate `ACTUAL_COMPONENT_PROFILE` namespace. Child admission
also requires the living original controller's immutable claim. Expiration
never moves when the child starts. One-thread/native environment is checked
again in each fresh interpreter, and every staged ledger member is rehashed.

The parent reserves a single pair allowance. Before launching each fresh
child it subtracts already consumed parent/waited-child CPU and wall, and
passes only the remainder. Each child installs CPU/alarm backstops; Slurm
memory/cgroup/job limits are separately required by admission. Failed, partial
or timed-out output remains; there is no automatic retry, resume or deletion.
Completed partial components cannot receive campaign-completion credit.

## Measurement and parity

Each lifecycle boundary records before/after self and waited-child CPU, wall,
physical and character IO, faults, context switches, current RSS and process /
waited-child high-water RSS. Nested phase counters are made disjoint; all
unattributed interval residuals are explicit. RSS high-water observations are
never added as a concurrency estimate. PID, start ticks, affinity, cgroup,
thread controls, exact sources/request/authority/task/runtime are retained.
Fresh interpreters prevent reuse of the accepted adapter's fixed module names.

Raw reference and instrumented NPZs, every chunk seal/result, phase journals,
logs and full results remain. The parity verifier binds both full components
to the reviewed task/source/request/job/scope/runtime, verifies retained
artifact seals, and streams every NPY member's exact dtype, shape, C order and
ordered element bytes. It compares the original sampler/RNG metadata and full
result/metrics exactly. Signed zero differences fail. It retains both packet
hashes; different ZIP timestamps may change container bytes while exact array
bytes agree. No numerical tolerance is added or loosened.

`profile_result.json` and `component_complete.json` counters are explicitly
pre-seal snapshots. `post_seal_accounting.json` includes the final seal's
hashing/serialization phase; publication of that last receipt and interpreter
exit remain a declared tail. Canonical collected Slurm primary allocation
CPU includes the entire job and is charged once. Self/child/step counters
attribute that charge and are never added as another charge. Parent IO does
not claim to contain child IO. Scientific memory/concurrency admission needs
collected aggregate cgroup/Slurm evidence; per-phase RSS alone is insufficient.

## Reproduction

Administrative verification, with the existing stdlib-only Python on CPU31:

```text
PYTHONDONTWRITEBYTECODE=1 TMPDIR=/dev/shm taskset -c 31 <r137-python> -B \
  -m unittest pricefm_hb.execution_profile_tests
```

From an independently admitted one-CPU compute allocation, with the exact
qualified environment and package source closure:

```text
<qualified-python> -B -m pricefm_hb.execution_profile \
  --request <request.json> --authority <authority.json> \
  --attestation <attestation.json> --output <authorized-ACTUAL_COMPONENT_PROFILE-root>
```

The internal `--component-child` mode is gated again and cannot replace the
required paired controller claim. A successful pair is qualification evidence
only. New accepted measurement coverage, pricing, worst-case memory, funding,
the complete optional scientific calendar and shared-controller admission
remain separate gates before any wider screening.
