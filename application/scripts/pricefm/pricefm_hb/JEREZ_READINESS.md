# Separate Jerez preparation route

`jerez_readiness.py` generates a bounded, read-only remote metadata program and
the exact SSH argv needed to run it. It does not submit scientific work or use
the Muscat-only r164 grant/owner/permit protocol. Its result always retains
`numerical_admission=false`.

The remote program runs on administrative CPU31 with8CPU/60wall limits. A
caller must bind source, argv, scope and start intent and run that command once
under the unchanged original H8CPU/90wall supervisor. Record the complete
supervisor receipt, exact command PID/birth, all-owned-tree drain and remote
CPU separately. The implementation adds no automatic retry. This read-only
Jerez program is not permitted on a Hummingbird login host.

Only exact previously recorded installed R4.6 runtime/package/shared-object
files are hashed. No R interpreter is started and no scientific result/data
payload is deserialized. Topology, available RAM, free disk and same-UID
numerical identities intersecting candidate pair30/62 are observed. Process
arguments remain redacted; emitted identities are not newly reviewed or
allowed peers. The observer never signals or moves any existing process.

Byte equality with Muscat is evidence for installed-file identity, not runtime
startup, ABI, numerical parity or host authority. The existing r164 launcher
fixes Muscat and pair30/62 and retains the original192GiB RAM/80GiB disk floors.
Jerez's existing50GiB baseline floor is reported separately and does not relax
that original guard. A future host-specific numerical route needs its own
source/guard qualification, finite resource policy, approved peer identities,
owner/lock/target authority, numerical parity, bridge and complete cost. This
metadata adapter issues none of those.

Metadata-only tests in `jerez_readiness_tests.py` validate that matching runtime
bytes cannot yield admission, an incorrect host or scientific/peer mutation is
rejected, Jerez50 is not relabeled as Muscat80, and the generated remote program
parses without executing numerical code or importing numerical modules.
