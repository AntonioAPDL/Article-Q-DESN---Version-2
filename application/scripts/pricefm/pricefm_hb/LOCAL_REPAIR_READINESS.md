`local_readiness.py` performs one bounded metadata observation on administrative
CPU31. It invokes the original `525_owned_stage_guard.py` physical primitive
without modifying that source, its sealed peer census, pair30/62, RAM192GiB or
disk80GiB floors. It creates no lock, claim, owner admission or numerical job.
Unknown numerical peers remain blockers. The separate installed-runtime audit
hashes the exact R4.6 executable, Rscript, loaded shared objects and installed
exdqlm package files as opaque bytes; no R or scientific payload is evaluated.

The output always says `numerical_admission=false`, even if every observed
prerequisite passes. A fresh physical snapshot is instantaneous. Full source
publication, EE/LV/successor success and drain, current reviewed physical census,
exact owner admission, original flock identity, finite new funding, accepted
native runtime/helper proof and the existing r164 synthetic-toy grant remain
required by `repair_authority.py`. That existing launcher is Muscat-only and
does not implicitly admit Jerez. Old clocks, failed attempts and paid balances
remain untouched.

Request schema: `r178_local_readiness_request_v1`, purpose
`METADATA_PREREQUISITES_ONLY`,20CPU/60wall, affinity `[31]`, exact original guard,
census and runtime pins, zero signals/optimizers/new peer allowances, a fresh
scope pin and a new exact output directory. The output directory is create-only.
Use the pinned Python3.11 interpreter and supply the exact request SHA:

```text
python -I -B -c '... insert the frozen pricefm source path and call
pricefm_hb.local_readiness.main(...) ...'
  --request <exact metadata request> --request-sha256 <SHA> --output <new directory>
```

`repair_diagnostic_packets.py` compiles the pinned original LT scalar analysis
and the saved NO4 failure classification into immutable diagnostic packets.
It retains Normal2000/AL300, all seven independent limits, both RHS starts and
zero posterior fits/production acceptance. The packets do not issue numerical
authority or infer a repaired certificate.

LT's first question explicitly concerns the same rounded binary64 precision
and RHS, with original beta/covariance units and original RHS prior. It is
separate from higher-precision construction from X/W. Full covariance accuracy
cannot be claimed from sampled probes or a different matrix norm. The packet
requires independently validated reference/precision stability, a synthetic
benchmark and complete source-context cost before any target. Boost100/BH is
only a candidate implementation; header availability is not a compiled,
benchmarked or accepted reference. Unsupported objective-only rearrangement,
AL600 and certificate overlays remain rejected.

NO4's packet binds its eight saved AL300 failures, repeated normalized-gate
patterns and separate144 RHS precision exclusions. It requires one predeclared
mechanism/target and a complete target/initializer/source/prior/scaler binding,
not automatic replay of every failure. A diagnostic does not release dependent
campaign tasks. A fallback requires complete frozen quantile/fold confirmation.

```text

pricefm_hb.local_readiness_tests and pricefm_hb.repair_diagnostic_packets_tests ...'
```
