# Exact NO3 pilot preparation contracts

These tools prepare a separate future NO3 AL300 purpose. They do not add a
pilot role to the live toy/bridge dispatcher, import a factor state, read a
scientific array or issue execution authority. Every generated package remains
`PREPARED_METADATA_CONTRACTS_PILOT_UNADMITTED`.

The scientific case is fixed in `pilot_preparation.CASE`: the original NO3
target, AL300, one attempt and at most one optimizer invocation, seed819509105,
zero-centered rhs_ns prior, original units, finite AND(formal OR independent),
all seven original independent limits and both RHS starts. Existing five
scientific sources and the stock body remain unchanged.

## Prepare a package

Run the pinned Python3.11 on administrative31 with metadata-only inputs:

```bash
PYTHONDONTWRITEBYTECODE=1 taskset -c 31 nice -n 19 ionice -c 3 /path/to/pinned/python -I -B /reviewed/tree/application/scripts/pricefm/pricefm_hb/pilot_preparation.py --input /absolute/input.json --output /absolute/new_preparation.json
```

The input has exactly four keys:

- `controller`: the proposed independently reviewed controller commit, branch
  and closed application-file SHA256 map. For a preparation-only source map,
  this remains a preparation identity and is not an implemented pilot owner.
- `bridge`: null until a real accepted bridge exists; otherwise the exact
  eventual bridge binding descriptor described by `validate_bridge_binding`.
- `aliases`: null with a missing bridge; otherwise exactly X and y, each
  preserving the old logical path/hash/length and one distinct physical path.
- `retention`: null while sizes are unmeasured; otherwise exact file
  descriptors, completed_sweeps and a finite envelope for validation.

Only bounded, regular, single-link JSON inputs are read. Duplicate keys,
nonfinite constants, symlinks, traversal, binary extensions and output
overwrite are rejected. The immutable numerical contract is imported by an
explicit sibling path so isolated `-I -B` invocation works.

## Preserve actual scientific provenance

A future accepted bridge may be produced by a newer reviewed owner. Preserve
its entire actual scientific source object (`kind/head/branch`) and the five
frozen scientific file hashes. Do not force the historical W187 commit or
relabel old JSON/RDS to match a new controller. Controller and scientific
identities remain separate even when they refer to different commits.

The future bridge descriptor closes ten proof pins: actual acceptance,
healthy outer guard, result, accounting, independent review, complete return,
finalization, bridge validation, factor state and baseline certificate.
It also records original manifest, target/posterior key, units/prior, original
failed bindings and the exact X/y references. This module validates the shape
and immutable metadata only. It deliberately requires
`acceptance_chain_independently_verified=false`; an input JSON claim cannot
earn independent acceptance. The actual proof chain must be reconciled by a
separately reviewed verifier.

`import_verification_interface` defines the missing compute-owned verifier.
It must execute after the current owned job's native TSYNC/parent ACK and
before frozen factor import/optimizer invocation. It must verify the stored
RDS source_provenance, original failed bindings, target/kind/origin, prior,
X/y aliases/hash/length/UID/path, unchanged factor validator and explicit factor
objective. Same-path reuse and one-to-one byte-equivalent relocation are
represented without rewriting old provenance. Metadata validation here never
claims RDS values or current kernel ownership were verified.

The future owner/worker/peer must implement and qualify that interface. This
lane does not install an R hook into the frozen port or claim runtime proof.

## Retain every checkpoint and return useful data

`retention_plan` accepts descriptor metadata for every completed sweep1..N,
where1<=N<=300. The exact remote set retains both `full_state.rds` and
`completed_evidence.json` for every sweep, the original checkpoint index,
final state, full independent certificate, terminal core containing stripped
all-seven certificate, beta mean/covariance and complete trace. Six separately
named proof/reproduction members are required by this future contract.

The useful main-return set contains all core/proof members and checkpoint
pairs for unique{1,ceil(N/2),N}. Selection depends only on completed sweep count.
The returned outer manifest must carry the complete `remote_retained`
hash/length inventory produced by the plan; that inventory is not a
self-referential file in its own hash set. Complete Slurm accounting, review,
guarded acceptance and finalization are separate enclosing proof-chain records
and must also be retained on the main server.

Descriptor validation checks exact membership, all sweeps, safe unique paths,
hashes/lengths, total/per-file envelopes, the next-write reserve and filesystem
reservation. Existing16MiB per-file/64MiB useful-return caps cannot be raised by
this tool. Oversized useful output remains blocked.

These checks do not measure serialized RDS sizes or price retention. A future
owned compute implementation still needs complete remote byte verification,
current disk/quota proof, a worst-case300-sweep capacity/CPU/wall envelope,
pre-write bounds that cover the next file, and explicit finite retention.
The frozen hook currently checks total size after writing; this contract
does not silently fix that runtime gap or delete checkpoints to make it fit.

## Required next evidence

1. Resolve and actually accept the exact real-target bridge.
2. Independently reconcile its full immutable proof chain.
3. Implement/review a separate pilot owner, worker, controller and two-phase
   peer, preserving source separation and the compute import interface.
4. Qualify new glue in separately funded compute; preparation source tests do
   not establish numerical or runtime parity.
5. Measure and independently accept complete source-context CPU/wall/memory,
   remote storage/retention, exact return and review/closeout costs. Toy and
   zero-update timings do not price AL300.
6. Publish the exact source and issue a genuinely new fully funded scope with
   fresh resource and kernel admission.
7. Run at most the one fixed pilot, then complete independent return review,
   guarded acceptance, finalization and hash-verified useful-data retrieval.

Pilot acceptance is not production promotion, exact optimizer resume,
replacement of the old failed fit or automatic AT/LT/NO4 release. Official
test scores cannot select this purpose. Old scopes, fees and clocks stay closed.

## Tests

`pilot_preparation_tests.py` covers missing/forged bridge metadata, different
controller/scientific commits, unchanged math hashes, one-to-one relocation,
closed input sets, all300 checkpoint descriptors, deterministic selection,
missing middle sweeps, immutable return caps, storage reserves, malformed
JSON/paths/booleans and actual isolated CLI invocation. It executes no R,
scientific array interpretation or optimizer.
