# One-shot submit to release driver

This local metadata driver addresses the120-second READY window missed during
chat-turn orchestration. It changes no compute file, H source, R fixture,
resource gate, current failed receipt or deadline. Namespace-only support is
bound to the independently authored reviewer source approval. It does not
qualify intrinsic handling, namespace/ABI, TSYNC or any numerical behavior.

Run the **direct driver file**, using the separately pinned LOCAL Python695bf
binary. Do not first import it through the W184 `pricefm_hb` package or use
`python -m`: that would cache W184 package resolution before the pinned W183
core is imported. Core `source_dir`, publication and source review remain on
exact W183 b998; the driver has its own source publication and independent
source review in `config.release_orchestration`. The core canonical identity
binds the entire added driver configuration. The remote HB cached Python6059
is not the local driver/reviewer interpreter.

The dated `DRIVER_BINDING_EXAMPLE_UNISSUED` artifact supplies the exact fields
and CLI. Null entries are requirements, not grants. The fresh invocation scope
funds parent SELF4 within root12, native136 and a separate independent READY12.
The parent inherited hard ceiling16 permits the existing child guardians and
reviewer to lower to their original4/6/12 limits. It does not enlarge their
hard ceilings. CPU reporting keeps parent, child guards and reviewer attribution
separate and does not charge a child both as SELF and waited CPU.

Start after one successful independently reviewed stage, with no JOB, submit
intent, failed-role marker or previous driver directory. The one invocation
durably records its intent, then:

1. Runs original H submit4/45 with the actual stage guard.
2. Settles once outside H for the configured1–15seconds.
3. Runs original H READY6/330 with the actual submit guard.
4. Prepares actual READY-bound unissued metadata specs through the exact W183
   core, then issues the fresh root install and owner authorities.
5. Invokes the immutable independently authored READY reviewer with its own
  12CPU allocation and exact existing CLI. That reviewer alone produces the
   install, owner and outer peer PASS records.
6. Checks every actual peer/output/context pin, writes the eight-file root
   release document last, then runs original H release4/180 with the actual
   READY guard.

The causal clock starts before submission. Every phase and final publication
must remain below80seconds from that anchor, conservatively bounding READY age
without assuming synchronized clocks or a missing READY creation timestamp.
No window is increased. A slow native action or reviewer is allowed to finish
under its existing owner; it cannot authorize a late successor release. The
reviewer has a SELF CPU cap and no added wall stopper. Filesystem/transport
stalls may therefore leave an invocation awaiting its current child, while the
compute job's unchanged window expires. No new killing wrapper is introduced.

Every native H child independently owns and drains its command. The driver
adds no process-group signal, timeout kill, automatic retry, watcher, detached
resubmission or unguarded SSH/R command. Failures retain receipts, phase records
and prospective grants. A failed submit or READY stops before release. A failed
release guard may occur after the remote pointer was published, so it is
explicitly recorded as **remote payload possibly started** and requires later
exact owned-job reconciliation. It never implies that no R ran.

A successful driver result proves only guarded submission, READY review and
release transport. Supply its actual release guard as `--previous-guard` to
the next normal core action. Complete accounting, return, independent runtime
review, accept and final guard validation remain mandatory. Old job887360 stays
failed and spent; this driver never resumes or reuses it.
