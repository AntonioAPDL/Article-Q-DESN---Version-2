## Verification design

An explicit, baseline-bound essential-content contract extends the existing
semantic validator. Earlier contracts and historical receipt namespaces remain
unchanged. Live source and copied-fixture tests are distinct: a portable
mutation fixture does not authenticate Git ancestry or qualify a scientific
campaign. Missing or partial version markers fail closed.

Acceptance requires deterministic caption reproduction; frozen-source and
numerical identity checks; mandatory consumer/archived-role checks; focused
mathematical, IND, MQ, streamflow-authority and presentation regressions; clean
references and four identified/anonymous manuscript builds; inspection at
actual page size; and an independently compiled clean article-only projection.
Source and integration commits are separate. Main and article-snapshot pushes
use the existing guarded command-line Git workflow with fresh remote readback.

Build counts and final receipts are recorded after validation, not inferred
from the page target. No broad scientific campaign is repeated merely to
validate an editorial change. Public source maps retain all omitted evidence.
