## Storage and accounting

The 64 MiB useful return limit includes payload, manifest and every mandatory proof. Each file is at most 16 MiB. Payload fits inside 64 MiB minus the return-proof reservation, which is at least 16 MiB. Physical proof storage is a separate minimum 64 MiB. Fixed payload slots plus proofs are physically reserved and consumed; no double reservation is counted as free capacity.

The unchanged original tracer also needs up to 32 MiB of transient old-plus-tmp tree evidence under its 16 MiB per-file limit. This is separately priced and protected by live disk headroom; it is not claimed physically preallocated. Initial/LT/NO4 plans therefore reserve respectively 112/288/608 MiB before mandatory headroom, subject to the stricter initial quote minimum. Runtime peak/completeness still require actual qualification. Failed partials and unused reservations stay retained.

Every compute subject remains direct Slurm outside original administrative H. Every administrative acceptance requires its own real H5; every publication phase its own real H8. Never fabricate a guard or reuse source metadata as actual runtime evidence. Full old and failed fees remain in the whole ledger. No automatic retry, requeue, cleanup, data deletion or future polling is authorized.
